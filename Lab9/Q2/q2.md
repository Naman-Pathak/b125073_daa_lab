# Huffman Coding

## Problem Statement

Given a set of symbols and their frequencies, construct a **prefix-free binary code** having the **minimum expected length**.

After constructing the Huffman code, output the **canonical Huffman codebook**, where symbols are ordered according to:

1. Increasing code length
2. Lexicographic order of symbols when code lengths are equal

The program should be implemented in **C**, and its complexity should be derived.

---

# 1. What is Huffman Coding?

Huffman Coding is a **greedy algorithm** used to construct an optimal prefix-free binary code.

It assigns:

- **Shorter codes** to frequently occurring symbols.
- **Longer codes** to less frequently occurring symbols.

For example, if:

```text
A → 45
B → 13
C → 12
D → 16
E → 9
F → 5
```

where the numbers represent frequencies, `A` occurs most frequently.

Therefore, `A` should receive a shorter code than symbols such as `E` and `F`.

The objective is to minimize the **expected code length**.

---

# 2. Prefix-Free Code

A code is called **prefix-free** if no codeword is a prefix of another codeword.

For example:

```text
A → 0
B → 10
C → 110
D → 111
```

is prefix-free.

Here:

- `0` is not a prefix of any other code.
- `10` is not a prefix of any other code.
- `110` is not a prefix of `111`.

Therefore, the codes can be uniquely decoded.

### Non-prefix-free example

```text
A → 0
B → 01
```

This is invalid because `0` is a prefix of `01`.

---

# 3. Expected Code Length

If symbol `i` has:

- frequency `fi`
- code length `li`

then its contribution to the total cost is:

```text
fi × li
```

Therefore, the total weighted code length is:

\[
L = \sum_{i=1}^{n} f_i l_i
\]

If the frequencies are probabilities, `L` represents the expected code length.

Huffman coding minimizes this value among all binary prefix-free codes.

---

# 4. Greedy Idea

The main greedy observation is:

> The two symbols with the smallest frequencies should be placed deepest in the Huffman tree.

Therefore, repeatedly:

1. Select the two nodes with the smallest frequencies.
2. Combine them into a new node.
3. Give the new node a frequency equal to their sum.
4. Insert the new node back.
5. Repeat until only one node remains.

A **Min Heap** is used to efficiently obtain the two smallest frequencies.

---

# 5. Example

Consider:

```text
Symbol    Frequency
A            45
B            13
C            12
D            16
E             9
F             5
```

Initially:

```text
5, 9, 12, 13, 16, 45
```

### Step 1

Take the two smallest:

```text
5 + 9 = 14
```

Now:

```text
12, 13, 14, 16, 45
```

### Step 2

Take:

```text
12 + 13 = 25
```

Now:

```text
14, 16, 25, 45
```

### Step 3

Take:

```text
14 + 16 = 30
```

Now:

```text
25, 30, 45
```

### Step 4

Take:

```text
25 + 30 = 55
```

Now:

```text
45, 55
```

### Step 5

Take:

```text
45 + 55 = 100
```

The Huffman tree is now complete.

---

# 6. Huffman Tree

The resulting tree can be represented conceptually as:

```text
                    100
                   /   \
                 45     55
                       /  \
                     25    30
                    / \    / \
                  12  13  14  16
                           / \
                          5   9
```

Assign:

```text
Left edge  → 0
Right edge → 1
```

Then the code of a symbol is obtained by following the path from the root to that symbol.

One possible Huffman code is:

```text
A → 0
B → 100
C → 101
D → 111
E → 1101
F → 1100
```

Different left/right choices can produce different codes while maintaining the same optimal code lengths.

This is why **canonical Huffman coding** is useful.

---

# 7. What is Canonical Huffman Coding?

A Huffman tree can produce multiple valid optimal codebooks.

For example, swapping the left and right children of a node changes the actual bit patterns while preserving their lengths.

Canonical Huffman coding provides a **standardized way of assigning the actual codes from the code lengths**.

The important idea is:

> First determine the optimal code length of every symbol, then generate the actual codes in a fixed canonical order.

---

# 8. Canonical Ordering

The symbols are sorted according to:

### First priority

Code length in increasing order.

### Second priority

Symbol in lexicographic order.

For example:

```text
Symbol    Length

A           1
B           3
C           3
D           3
E           4
F           4
```

The ordering is:

```text
A, B, C, D, E, F
```

---

# 9. Generating Canonical Codes

Suppose the code lengths are:

```text
A → 1
B → 3
C → 3
D → 3
E → 4
F → 4
```

Start with:

```text
A → 0
```

For the next code of the same length, increment the previous code.

Because the next code has length `3`, the code is shifted left appropriately.

The canonical codes become:

```text
A → 0
B → 100
C → 101
D → 110
E → 1110
F → 1111
```

These codes are prefix-free and correspond to the same optimal code lengths.

# 10. Algorithm

## Step 1: Read Input

Read:

- Number of symbols `n`
- Symbol
- Frequency of each symbol

Represent a symbol using:

```c
typedef struct {
    char symbol;
    int frequency;
    int length;
    unsigned int code;
} Symbol;
```

---

## Step 2: Create Huffman Nodes

Create one tree node for every symbol.

Each node contains:

```text
symbol
frequency
left child
right child
```

---

## Step 3: Insert Nodes into a Min Heap

All nodes are inserted into a min heap based on frequency.

The root of the heap always contains the node with the smallest frequency.

---

## Step 4: Build the Huffman Tree

While more than one node remains:

```text
left  = extract minimum
right = extract minimum

parent.frequency =
    left.frequency + right.frequency

parent.left = left
parent.right = right

insert parent into heap
```

Continue until only one node remains.

That node is the root of the Huffman tree.

---

# 11. Finding Code Lengths

Traverse the Huffman tree.

Whenever we move:

```text
Left  → add 0
Right → add 1
```

The depth of a leaf represents the code length.

For example:

```text
Root
 |
 0
 |
 A
```

means:

```text
A has code length 1
```

If a symbol is three edges away from the root, its code length is `3`.

We only need the **lengths** at this stage.

---

# 12. Generate Canonical Codes

After finding the code length of every symbol:

1. Sort symbols by `(length, symbol)`.
2. Set the first code to `0`.
3. For every next symbol:
   - Increment the previous code.
   - Shift left if the new code length is greater.
4. Store the resulting code.

---

# 13. Pseudocode

```text
HuffmanCoding(symbols):

    Create a min heap

    for every symbol:
        create a leaf node
        insert node into min heap

    while heap contains more than one node:

        x = extract minimum
        y = extract minimum

        create new node z

        z.frequency = x.frequency + y.frequency
        z.left = x
        z.right = y

        insert z into heap

    root = remaining node

    Find code length of every symbol
        by traversing the tree

    Sort symbols by:
        1. code length
        2. symbol

    Generate canonical codes

    Output the canonical codebook
```

### Huffman Tree Node

```c
typedef struct Node {
    char symbol;

    struct Node *left;
    struct Node *right;
} Node;
```

### Min Heap

```c
typedef struct {
    Node *heap[MAX_SIZE];
    int size;
} MinHeap;
```

The min heap is used to efficiently find the two nodes having the smallest frequencies.

---

# 15. Why Min Heap?

Without a heap, we could search the entire collection to find the two minimum frequencies.

That would be inefficient.

A min heap provides:

```text
Insert       → O(log n)
Extract Min  → O(log n)
```

Therefore, Huffman tree construction becomes efficient.

---
