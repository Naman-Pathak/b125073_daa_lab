# Minimum Number of Meeting Rooms

## 1. Problem Statement

Given an array of meeting time intervals in the form `[start, end]`, find the minimum number of conference rooms required to hold all meetings without overlapping meetings sharing the same room.

**Example:**

Input:

`[[0, 30], [5, 10], [15, 20]]`

Output:

`2`

**Explanation:**

- Meeting 1 takes place from 0 to 30.
- Meeting 2 takes place from 5 to 10.
- Meeting 3 takes place from 15 to 20.

Meeting 1 overlaps with both Meeting 2 and Meeting 3. However, Meetings 2 and 3 do not overlap, so they can use the same room.

Therefore, the minimum number of rooms required is **2**.

## 2. Input Representation

In C, represent the input using:

- An integer `n`, representing the number of meetings.
- A structure containing two integers: `start` and `end`.
- An array of structures to store all meeting intervals.

For example:

```c
typedef struct {
    int start;
    int end;
} Meeting;
```

Each element of the array stores the starting and ending times of one meeting.

## 3. Algorithm Approach: Sorting and Min-Heap

A **Min-Heap** is a data structure in which the smallest element is always available at the root.

In this problem, the heap stores the ending times of meetings currently assigned to rooms.

### Steps

1. Read the number of meetings and their start and end times.
2. Sort all meetings in increasing order of their starting times.
3. Insert the ending time of the first meeting into the Min-Heap.
4. For each subsequent meeting:
   - Check the smallest ending time in the heap.
   - If that ending time is less than or equal to the current meeting's starting time, remove it because the room can be reused.
   - Insert the current meeting's ending time into the heap.
   - Update the maximum heap size reached.
5. Return the maximum heap size as the minimum number of conference rooms required.

**Important condition:** If a meeting ends at time `t` and another starts at time `t`, the same room can be reused.

## 4. Dry Run

Consider the input:

`[[0, 30], [5, 10], [15, 20]]`

The meetings are already sorted by starting time.

| Meeting | Start | End | Action | Heap size |
|---|---:|---:|---|---:|
| 1 | 0 | 30 | Allocate a room | 1 |
| 2 | 5 | 10 | Meeting 1 is still running; allocate another room | 2 |
| 3 | 15 | 20 | Meeting ending at 10 has finished; reuse its room | 2 |

The maximum heap size is 2.

**Final output: `2`**

## 5. Why Does the Algorithm Work?

- **Sorting:** Processing meetings in starting-time order ensures that each new meeting is considered chronologically.
- **Min-Heap:** The root gives the earliest ending time among meetings currently assigned to rooms.
- **Room reuse:** If the earliest ending meeting has finished, at least one room is available for the current meeting.
- **Counting rooms:** The heap stores the ending times of meetings occupying the rooms. Its size indicates how many rooms are currently needed
