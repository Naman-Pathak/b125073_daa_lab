1. Problem Statement
An undirected graph is bipartite if its vertices can be divided into two sets such that every edge connects vertices from different sets. A graph is bipartite if and only if it contains no odd-length cycle.
In this problem, edges arrive one at a time. For each incoming edge (u, v):
- Accept the edge if adding it preserves bipartiteness.
- Reject the edge if it would create an odd-length cycle.
- Keep all previously accepted edges unchanged.
2. Approach
Use a Disjoint Set Union (DSU) with parity information to track connected components and the relative colors of their vertices.
Imagine assigning every vertex one of two colors: 0 or 1. Every accepted edge must connect vertices of opposite colors.
The DSU maintains three pieces of information:
- Parent: identifies the parent of each vertex in the DSU forest.
- Size: records the size of each component, allowing smaller components to be merged into larger ones.
- Parity: records whether a vertex has the same or opposite color as its parent. After finding the component representative, parity gives the color difference between the vertex and the representative.
Processing each incoming edge (u, v)
1. Find the component representatives: Use the DSU find operation for both endpoints. Path compression makes future searches faster.
2. If both endpoints are in the same component: Their relative colors are already determined.
   - If their colors are different, accept the edge.
   - If their colors are the same, reject the edge because it would create an odd-length cycle.
3. If the endpoints are in different components: Merge the components. Choose the relative coloring so that u and v have opposite colors. Union by size keeps the DSU tree shallow.
4. Continue with the next edge.
The algorithm checks each edge as it arrives and does not need to store the entire graph in an adjacency matrix or adjacency list.
3. Why the Approach Works
The key property is that every accepted edge must connect vertices of opposite colors.
- Endpoints in different components: The two components can be oriented relative to each other so the new edge connects opposite colors. Merging them preserves bipartiteness.
- Endpoints in the same component: If the endpoints already have opposite colors, the edge is consistent with the existing coloring and can be accepted. If they have the same color, every path between them has even length; adding the new edge creates an odd-length cycle, so it must be rejected.
Therefore, the algorithm accepts only edges that preserve bipartiteness.
4. Example
Suppose there are four vertices and the edges arrive in this order:
(1, 2), (2, 3), (3, 4), (4, 1), (1, 3)
- The first four edges are accepted. They form a cycle of length four, which is even.
- The edge (1, 3) is rejected. Vertices 1 and 3 already have the same color, and adding this edge creates the triangle 1 → 2 → 3 → 1, a cycle of length three.
The graph formed by the accepted edges remains bipartite.
5. Complexity Analysis
Let V be the number of vertices and E the number of incoming edges.
- Initialization: O(V)
- Processing one edge: amortized O(α(V))
- Total time complexity: O(V + E α(V))
- Auxiliary space complexity: O(V)
Here, α(V) is the inverse Ackermann function, which grows extremely slowly and is effectively constant for practical input sizes.
The space complexity is O(V) because the DSU stores parent, size, and parity information for each vertex, without storing the full graph.
6. Conclusion
A parity-based DSU provides an efficient way to test graph bipartiteness online. It processes edges one by one, accepts edges that preserve bipartiteness, and rejects edges that would create odd-length cycles. With path compression and union by size, the algorithm has amortized time complexity O(V + E α(V)) and auxiliary space complexity O(V).
