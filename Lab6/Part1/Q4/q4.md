## Question 4: Matrix Chain Multiplication Using Dynamic Programming
### Problem Statement
Implement the Matrix Chain Multiplication algorithm using Dynamic Programming.

Given a sequence of matrices, determine the order in which the matrices should be multiplied so that the total number of scalar multiplications is minimized.

### Introduction

Matrix Chain Multiplication is an optimization problem.

When several matrices are multiplied together, the final result remains the same regardless of how the matrices are parenthesized, provided the order of the matrices is not changed.

However, different orders of multiplication can require different numbers of scalar multiplications.

Therefore, the objective is to find the order of multiplication that requires the minimum number of scalar multiplications.

### Important Concept

Matrix multiplication is associative.

For three matrices A, B, and C:

(A × B) × C

and

A × (B × C)

produce the same final matrix.

However, the number of calculations required can be different.

Therefore, we are not changing the order of the matrices. We are only changing the position of the parentheses.

### Example

Consider three matrices:

A = 10 × 30

B = 30 × 5

C = 5 × 60

There are two possible ways to multiply them.

#### Method 1: (A × B) × C

First multiply A and B.

Cost:

10 × 30 × 5 = 1500

The resulting matrix has dimensions:

10 × 5

Now multiply the result with C.

Cost:

10 × 5 × 60 = 3000

Total cost:

1500 + 3000 = 4500

#### Method 2: A × (B × C)

First multiply B and C.

Cost:

30 × 5 × 60 = 9000

The resulting matrix has dimensions:

30 × 60

Now multiply A with the result.

Cost:

10 × 30 × 60 = 18000

Total cost:

9000 + 18000 = 27000

Therefore:

(A × B) × C

requires only 4500 scalar multiplications, while:

A × (B × C)

requires 27000 scalar multiplications.

Hence, the optimal order is:

(A × B) × C

with a minimum cost of:

4500 scalar multiplications.

### Dynamic Programming Approach

The Matrix Chain Multiplication problem can be solved using Dynamic Programming because the problem contains overlapping subproblems and optimal substructure.

A two-dimensional DP table is used.

Let:

dp[i][j]

represent the minimum number of scalar multiplications required to multiply matrices from Ai to Aj.

The objective is to calculate dp[1][n], which represents the minimum cost of multiplying the complete matrix chain.

### Representation of Matrix Dimensions

Suppose the dimension array is:

10, 30, 5, 60

Then the matrices are:

A1 = 10 × 30

A2 = 30 × 5

A3 = 5 × 60

In general, if the dimension array is:

p0, p1, p2, ..., pn

then:

Ai = p(i-1) × pi

This representation makes it easier to calculate the cost of multiplying matrices.

### Working

The algorithm considers different lengths of matrix chains, starting with chains containing only one matrix.

#### Chain of One Matrix

Multiplying a single matrix requires no multiplication.

Therefore:

dp[i][i] = 0

#### Chain of Multiple Matrices

For a chain containing more than one matrix, the chain can be divided at different positions.

For example:

A1 A2 A3 A4

can be divided as:

(A1) × (A2 A3 A4)

or:

(A1 A2) × (A3 A4)

or:

(A1 A2 A3) × (A4)

Every possible division is considered.

The algorithm calculates the cost for every possible division and stores the minimum cost.

### Recurrence Relation

If the chain Ai through Aj is divided after Ak, the total cost is:

Cost of multiplying Ai through Ak

+

Cost of multiplying A(k+1) through Aj

+

Cost of multiplying the two resulting matrices

The recurrence relation is:

dp[i][j] = min {
    dp[i][k] + dp[k+1][j]
    + p[i-1] × p[k] × p[j]
}

where:

i ≤ k < j

The algorithm tries every possible value of k and selects the minimum cost.

### Why Dynamic Programming Works

The same smaller matrix chains may occur while calculating different larger chains.

For example, the minimum cost of multiplying A2 through A4 may be needed while calculating the minimum cost of multiplying A1 through A4.

Instead of calculating the same smaller problem repeatedly, Dynamic Programming stores its result and reuses it.

This reduces unnecessary calculations.

### Initial Conditions

A single matrix does not require any multiplication.

Therefore:

dp[i][i] = 0

for every matrix i.

The DP table is then filled for increasing chain lengths.

### Important Observation

Matrix Chain Multiplication does not actually perform the matrix multiplication.

It only determines the optimal parenthesization and calculates the minimum number of scalar multiplications required.

For example, if the matrices are:

A1 × A2 × A3

the algorithm determines whether:

(A1 × A2) × A3

or:

A1 × (A2 × A3)

is more efficient.

### Time Complexity

For every pair of starting and ending matrices, all possible splitting positions are considered.

There are approximately O(n²) subproblems, and each subproblem can have O(n) possible splitting positions.

Therefore, the time complexity is:

O(n³)

### Space Complexity

A two-dimensional DP table is used to store the minimum multiplication costs.

The table requires approximately n × n entries.

Therefore, the space complexity is:

O(n²)

### Advantages of Dynamic Programming

- Finds the optimal matrix multiplication order.
- Avoids repeated calculations of the same subproblems.
- Significantly reduces the number of unnecessary scalar multiplications.
- Provides an efficient solution for a large number of matrices.
- Clearly demonstrates the concept of optimal substructure and overlapping subproblems.

### Conclusion

Matrix Chain Multiplication is an optimization problem in which the order of multiplying matrices is selected to minimize the number of scalar multiplications.

Dynamic Programming solves the problem by considering every possible way to split the matrix chain, calculating the cost of each split, and storing the minimum cost.

The final DP table entry gives the minimum number of scalar multiplications required to multiply the complete chain.

The algorithm has a time complexity of O(n³) and a space complexity of O(n²).
