# Q4 – Sorting a Permutation Using Reversal Operations

## Problem Overview

We are given a permutation `p` of the integers `1` to `n`. The objective is to sort it into:

`[1, 2, ..., n]`

The only allowed operation is:

`reverse(p, i, j)`

which reverses the subsequence from position `i` through position `j`.

The problem has two requirements:

1. Show mathematically that any permutation can be sorted using `O(n)` reversals.
2. When the cost of a reversal is its length, design an algorithm with total reversal cost `O(n log² n)`.

## Part 1 – O(n) Number of Reversals

Consider position `i`.

The correct value at this position is `i`.

Find the position `j` where value `i` currently occurs. If `j` is different from `i`, reverse the range from `i` to `j`.

After this reversal, the value `i` is placed at position `i`.

Then move to position `i + 1` and repeat.

At most one reversal is required for each position from `1` to `n - 1`.

Therefore the number of reversals is at most:

`n - 1`

Hence any permutation can be sorted using:

**O(n) reversals**

## Why O(n) Reversals Alone Is Not Sufficient

The cost of a reversal is its length:

`|j - i| + 1`

Although there are only `O(n)` reversals, a reversal may contain `O(n)` elements.

Therefore, simply placing one element at a time can result in a total cost of `O(n²)`.

The second requirement needs a better strategy.

## Part 2 – Divide and Conquer

The solution divides the values into two groups.

For a current value range `[low, high]`, calculate:

`mid = floor((low + high) / 2)`

The elements are partitioned into:

- values from `low` through `mid`
- values from `mid + 1` through `high`

The partition itself is performed using reversals only.

After partitioning, recursively sort the lower-valued group and the higher-valued group.

## Partition Using Reversals

Suppose the current arrangement contains four consecutive groups:

`L1 H1 L2 H2`

where:

- `L1` and `L2` contain lower-half values
- `H1` and `H2` contain upper-half values

We need to transform this into:

`L1 L2 H1 H2`

The middle two groups can be rotated using three reversals:

1. Reverse `H1`
2. Reverse `L2`
3. Reverse the combined `H1 L2`

This transforms the middle portion from:

`H1 L2`

into:

`L2 H1`

Thus the lower-valued elements become one contiguous group and the higher-valued elements become another contiguous group.

## Recursive Structure

The algorithm recursively performs the same operation on the lower and upper value ranges.

The value range is approximately halved at every level, so the recursion has:

`O(log n)`

levels.

## Cost of One Partition Level

At a particular recursive level, the total lengths of the reversal operations are proportional to the number of elements being processed.

Therefore, one complete partition level costs:

`O(n)`

There are `O(log n)` levels in the partition procedure.

So the cost of partitioning is:

`O(n log n)`

## Total Sorting Cost

Let `T(n)` represent the total reversal cost.

The divide-and-conquer recurrence is:

`T(n) = 2T(n/2) + O(n log n)`

At every level of the main recursion, the combined partition cost is `O(n log n)`. There are `O(log n)` levels.

Therefore:

`T(n) = O(n log n × log n)`

So:

**T(n) = O(n log² n)**

This satisfies the required cost bound.

## Correctness

At each recursive call, the partition operation places every value in the lower half before every value in the upper half.

The lower half is then recursively sorted, and the upper half is also recursively sorted.

Eventually, every range contains only one value, which is already sorted.

Combining the recursively sorted ranges produces:

`[1, 2, ..., n]`

Therefore, the algorithm correctly sorts every permutation.

## Complexity Summary

| Property | Result |
|---|---:|
| Maximum number of reversals for simple method | O(n) |
| Cost of simple method | Can be O(n²) |
| Recursion depth | O(log n) |
| Partition cost | O(n log n) |
| Total reversal cost | **O(n log² n)** |

## Conclusion

The simple placement method proves that any permutation can be sorted with only `O(n)` reversals, but it does not control the total length of those reversals. The divide-and-conquer method instead keeps the reversal cost under control by repeatedly partitioning the values into two halves. Its total reversal cost is **O(n log² n)** while using only the permitted reversal operation.
