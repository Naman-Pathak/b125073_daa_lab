# Q2 – 2D Square Matrix Operations and Their Complexities

## Problem Overview

The task considers square matrices having `n` rows and `n` columns. We determine the worst-case computational complexity of seven matrix operations and validate the procedures using a C implementation.

## Solution Approach

### 1. Matrix Addition

For every position `(i, j)`, add the corresponding elements of the two matrices.

There are `n²` positions.

**Worst-case complexity: O(n²)**

### 2. Matrix Multiplication

For every element of the result matrix, the corresponding row of the first matrix is multiplied with a column of the second matrix.

There are `n²` result elements, and each requires `n` multiplications/additions.

Therefore:

`n² × n = n³`

**Worst-case complexity: O(n³)**

### 3. Checking Whether the Matrix Is a Zero Matrix

Traverse all matrix elements and check whether every element is zero.

In the worst case, all `n²` elements must be examined.

**Worst-case complexity: O(n²)**

### 4. Checking Whether the Matrix Is Symmetric

A matrix is symmetric when:

`A[i][j] = A[j][i]`

Only the elements on one side of the main diagonal need to be compared with their corresponding elements on the other side. The number of comparisons is still proportional to `n²`.

**Worst-case complexity: O(n²)**

### 5. Computing the Determinant

The solution uses Gaussian-elimination-style processing. The matrix is transformed into an upper-triangular form, and the determinant is obtained from the diagonal elements, accounting for row swaps.

The elimination process contains nested operations whose total cost is cubic.

**Worst-case complexity: O(n³)**

### 6. Transposing the Matrix In Place

For an in-place transpose, swap:

`A[i][j]` with `A[j][i]`

for positions above the main diagonal.

No second matrix is required.

The number of required swaps is proportional to `n²`.

**Worst-case complexity: O(n²)**

The important point is that the transpose is performed **in situ**, so the extra matrix storage is avoided.

### 7. Finding an Eigenvalue and Eigenvector

The implementation uses the power-method approach to obtain a dominant eigenvalue and its corresponding eigenvector.

Each iteration performs a matrix-vector multiplication, which requires `O(n²)` work. If `k` iterations are performed, the complexity is:

**O(k n²)**

For a fixed number of iterations, this behaves as `O(n²)`. A complete eigenvalue/eigenvector decomposition generally requires a cubic-time algorithm.

## Complexity Summary

| Operation | Worst-Case Complexity |
|---|---:|
| Matrix Addition | O(n²) |
| Matrix Multiplication | O(n³) |
| Zero Matrix Check | O(n²) |
| Symmetric Matrix Check | O(n²) |
| Determinant | O(n³) |
| In-place Transpose | O(n²) |
| Dominant Eigenpair using Power Method | O(k n²) |

## Conclusion

Most basic matrix inspections and element-wise operations require `O(n²)` time because a square matrix contains `n²` elements. Operations involving three nested dimensions, such as ordinary matrix multiplication and Gaussian elimination for the determinant, require `O(n³)` time.
