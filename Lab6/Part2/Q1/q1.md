# Q1 – 1D Array Operations and Their Complexities

## Problem Overview

The task considers an unsorted array containing `n` integer elements. We need to determine the worst-case computational complexity of nine common array operations and implement procedures to validate the analysis.

## Solution Approach

### 1. Finding the Maximum Element

Start with the first element as the current maximum and scan the remaining elements one by one. Whenever a larger element is found, update the maximum.

Every element may need to be examined, so the worst-case complexity is:

**O(n)**

### 2. Finding the First and Second Largest Elements

Maintain two values while traversing the array: the largest and the second largest element found so far. Each new element is compared with these values and the appropriate one is updated.

Only one traversal is required.

**Worst-case complexity: O(n)**

### 3. Finding the Mean

Add all `n` elements and divide the sum by `n`.

The array must be traversed once.

**Worst-case complexity: O(n)**

### 4. Finding the Median

Because the input array is unsorted, the elements are first sorted. Merge sort can be used, which takes `O(n log n)` time. After sorting, the middle element, or the average of the two middle elements, gives the median.

**Worst-case complexity: O(n log n)**

### 5. Finding the Standard Deviation

First calculate the mean. Then traverse the array again to calculate the squared difference of every element from the mean and obtain the standard deviation.

Both traversals are linear.

**Worst-case complexity: O(n)**

### 6. Finding the Mode

Sort the array first. Equal values then occur next to one another, so a single scan can count consecutive equal values and determine the value with the highest frequency.

Sorting dominates the running time.

**Worst-case complexity: O(n log n)**

### 7. Removing All Duplicates

Sort the array so equal values become adjacent. Then scan the sorted array and keep only the first occurrence of each distinct value.

**Worst-case complexity: O(n log n)**

### 8. Reversing the Array

Swap the first element with the last, the second with the second-last, and continue until the middle is reached.

Approximately `n/2` swaps are performed.

**Worst-case complexity: O(n)**

### 9. Partitioning Around a Given Pivot

The required arrangement places elements greater than or equal to the pivot before elements less than the pivot. Scan the array and place elements into the two required groups.

Only a constant number of passes through the array is needed.

**Worst-case complexity: O(n)**

## Complexity Summary

| Operation | Worst-Case Complexity |
|---|---:|
| Maximum | O(n) |
| First and second largest | O(n) |
| Mean | O(n) |
| Median | O(n log n) |
| Standard deviation | O(n) |
| Mode | O(n log n) |
| Remove duplicates | O(n log n) |
| Reverse | O(n) |
| Partition | O(n) |

## Conclusion

The main idea is to choose an appropriate representation and algorithm for each operation. Operations that require only a single scan are linear, while median, mode, and duplicate removal require sorting and therefore take `O(n log n)` in the implemented approach.
