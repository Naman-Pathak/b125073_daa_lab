# Optimal Binary Search Trees (OBST)

## 1. Problem Statement

Given a set of `n` distinct sorted keys:

```text
K = {k1, k2, ..., kn}
```

with successful search probabilities:

```text
P = {p1, p2, ..., pn}
```

and `n + 1` dummy keys:

```text
D = {d0, d1, ..., dn}
```

with unsuccessful search probabilities:

```text
Q = {q0, q1, ..., qn}
```

construct a **Binary Search Tree (BST)** such that the **expected search cost is minimum**.

The program must:

1. Calculate the minimum expected search cost.
2. Determine the optimal root for each subtree.
3. Reconstruct the optimal Binary Search Tree.
4. Validate the Dynamic Programming algorithm using a C program.
5. Derive the time and space complexity.

---

# 2. Understanding the Problem

A normal Binary Search Tree is constructed based on the ordering of keys.

For example:

```text
k1 < k2 < k3 < k4
```

A possible BST is:

```text
        k2
       /  \
     k1    k3
             \
              k4
```

However, not every BST has the same search cost.

If some keys are searched much more frequently than others, it is better to place frequently searched keys closer to the root.

For example, if:

```text
p2 >> p1
```

then it may be beneficial to make `k2` closer to the root.

Similarly, dummy keys represent unsuccessful searches and also affect the expected search cost.

Therefore, the goal is to find the BST that minimizes the total expected search cost.

---

# 3. Successful and Unsuccessful Searches

There are two types of searches.

## 3.1 Successful Search

A successful search finds one of the actual keys:

```text
k1, k2, ..., kn
```

The probability of successfully finding `ki` is:

```text
pi
```

---

## 3.2 Unsuccessful Search

An unsuccessful search falls between two consecutive keys.

These searches are represented by dummy keys:

```text
d0, d1, ..., dn
```

For example:

```text
d0 < k1 < d1 < k2 < d2 < ... < kn < dn
```

Here:

* `d0` represents a search for a value smaller than `k1`.
* `d1` represents a search for a value between `k1` and `k2`.
* `d2` represents a search for a value between `k2` and `k3`.
* `dn` represents a search for a value greater than `kn`.

---

# 4. Expected Search Cost

Suppose a key is at depth `d`.

Its contribution to the expected search cost is:

$$
p_i(d+1)
$$

Similarly, a dummy key at depth `d` contributes:

$$
q_i(d+1)
$$

Therefore, the expected cost of a BST is:

$$
E =
\sum_{i=1}^{n} p_i(depth(k_i)+1)
+
\sum_{i=0}^{n} q_i(depth(d_i)+1)
$$

Our goal is to minimize this value.

---

# 5. Why Dynamic Programming?

There can be a very large number of different Binary Search Trees for `n` keys.

Trying every possible BST would be inefficient.

The problem has two important properties.

## 5.1 Optimal Substructure

Suppose `kr` is selected as the root of a subtree containing keys:

```text
ki, ki+1, ..., kj
```

Then:

```text
Left subtree  = keys ki ... k(r-1)
Right subtree = keys k(r+1) ... kj
```

For the overall tree to be optimal, both the left and right subtrees must also be optimal.

Therefore, the problem has optimal substructure.

---

## 5.2 Overlapping Subproblems

The same ranges of keys occur repeatedly while considering different possible roots.

For example:

```text
keys 1 ... 3
```

may be required while calculating multiple larger subtrees.

Dynamic Programming stores the results of these smaller subproblems so they do not have to be recalculated.

---

# 6. DP Tables

We use three important tables.

## 6.1 Expected Cost Table

Define:

```text
e[i][j]
```

as the minimum expected search cost of a subtree containing keys:

```text
ki, ki+1, ..., kj
```

along with the corresponding dummy keys.

---

## 6.2 Probability Table

Define:

```text
w[i][j]
```

as the total probability of all successful and unsuccessful searches associated with the subtree from `ki` through `kj`.

It contains:

```text
pi + pi+1 + ... + pj
```

and:

```text
q(i-1) + qi + ... + qj
```

Therefore:

$$
w[i][j]
=
\sum_{t=i}^{j}p_t
+
\sum_{t=i-1}^{j}q_t
$$

---

## 6.3 Root Table

Define:

```text
root[i][j]
```

as the key selected as the optimal root for the subtree containing keys:

```text
ki ... kj
```

This table is required to reconstruct the actual optimal BST.

Thus:

```text
e[][]     → minimum expected cost
w[][]     → total probability
root[][]  → optimal root
```

---

# 7. Base Case

Consider an empty subtree.

If there are no actual keys between two boundaries, there is only one dummy key.

For example:

```text
e[i][i-1]
```

represents the empty subtree containing dummy key:

```text
d(i-1)
```

Therefore:

$$
e[i][i-1]=q_{i-1}
$$

Similarly:

$$
w[i][i-1]=q_{i-1}
$$

This is the base case of the Dynamic Programming algorithm.

---

# 8. Probability Recurrence

For a subtree containing keys `ki` through `kj`:

$$
w[i][j]
=
w[i][j-1]+p_j+q_j
$$

This allows the probability sum to be calculated efficiently.

Instead of calculating all probabilities from scratch, we reuse the previously calculated value:

```text
w[i][j-1]
```

---

# 9. Choosing the Root

Suppose we are solving the subproblem:

```text
ki ... kj
```

We can choose any key:

```text
kr
```

where:

```text
i <= r <= j
```

as the root.

Then:

```text
Left subtree:
ki ... k(r-1)
```

and:

```text
Right subtree:
k(r+1) ... kj
```

The cost of choosing `kr` as root is:

$$
e[i][r-1]
+
e[r+1][j]
+
w[i][j]
$$

Why do we add `w[i][j]`?

Because when the entire subtree is moved one level below its parent, the depth of every key and dummy key increases by one.

Therefore, all probabilities in that subtree contribute one additional unit of cost.

---

# 10. OBST Recurrence

We try every possible root `r`.

Therefore:

$$
\boxed{
e[i][j]
=
\min_{i\le r\le j}
\left(
e[i][r-1]
+
e[r+1][j]
+
w[i][j]
\right)
}
$$

Whenever a root produces a smaller cost, we store:

```text
root[i][j] = r
```

---

# 11. Example

Consider three keys:

```text
K = {10, 20, 30}
```

Successful search probabilities:

```text
p1 = 0.30
p2 = 0.20
p3 = 0.10
```

Unsuccessful search probabilities:

```text
q0 = 0.05
q1 = 0.10
q2 = 0.10
q3 = 0.15
```

Check that all probabilities sum to 1:

$$
0.30+0.20+0.10+
0.05+0.10+0.10+0.15
=1
$$

---

# 12. Empty Subtree Values

The base cases are:

$$
e[1][0]=q_0=0.05
$$

$$
e[2][1]=q_1=0.10
$$

$$
e[3][2]=q_2=0.10
$$

$$
e[4][3]=q_3=0.15
$$

---

# 13. Subtree of Length 1

Consider key `k1`.

Its subtree can only have `k1` as its root.

Therefore:

$$
e[1][1]
=
e[1][0]
+
e[2][1]
+
w[1][1]
$$

The total probability is:

$$
w[1][1]
=
q_0+p_1+q_1
$$

$$
=0.05+0.30+0.10
$$

$$
=0.45
$$

Therefore:

$$
e[1][1]
=
0.05+0.10+0.45
=0.60
$$

Similarly, we calculate the costs for the other one-key subtrees.

---

# 14. Considering Different Roots

For the complete set:

```text
k1, k2, k3
```

we try:

```text
k1 as root
k2 as root
k3 as root
```

For `k1`:

```text
Left subtree  = empty
Right subtree = k2, k3
```

For `k2`:

```text
Left subtree  = k1
Right subtree = k3
```

For `k3`:

```text
Left subtree  = k1, k2
Right subtree = empty
```

The algorithm calculates all three possibilities and chooses the one with the smallest expected cost.

---

# 15. Reconstruction

The `root[][]` table stores the optimal root for every interval.

Suppose:

```text
root[1][3] = 2
```

Then:

```text
k2
```

is the root of the entire tree.

The left subtree is:

```text
root[1][1]
```

and the right subtree is:

```text
root[3][3]
```

We recursively repeat this process.

Thus, the `root[][]` table allows us to reconstruct the entire tree.

---

# 16. Algorithm

### Step 1

Read the number of keys `n`.

### Step 2

Read the successful search probabilities:

```text
p1, p2, ..., pn
```

### Step 3

Read the unsuccessful search probabilities:

```text
q0, q1, ..., qn
```

### Step 4

Initialize the empty-subtree cases:

```text
e[i][i-1] = q[i-1]
w[i][i-1] = q[i-1]
```

### Step 5

Consider subtree lengths from `1` to `n`.

### Step 6

For every interval `[i,j]`:

1. Calculate `w[i][j]`.
2. Set the initial cost to infinity.
3. Try every possible root `r`.
4. Calculate:

```text
cost = e[i][r-1] + e[r+1][j] + w[i][j]
```

5. Keep the minimum cost.
6. Store the corresponding root in `root[i][j]`.

### Step 7

The final answer is:

```text
e[1][n]
```

### Step 8

Use `root[][]` to reconstruct the optimal BST.

---

# 17. Pseudocode

```text
OBST(p, q, n)

    for i = 1 to n + 1
        e[i][i-1] = q[i-1]
        w[i][i-1] = q[i-1]

    for length = 1 to n

        for i = 1 to n-length+1

            j = i + length - 1

            e[i][j] = infinity

            w[i][j] =
                w[i][j-1] + p[j] + q[j]

            for r = i to j

                cost =
                    e[i][r-1]
                    + e[r+1][j]
                    + w[i][j]

                if cost < e[i][j]

                    e[i][j] = cost
                    root[i][j] = r

    return e[1][n]
```

# 18. C Implementation

```c
#include <stdio.h>
#include <stdlib.h>
#include <float.h>

#define INF DBL_MAX

void printOptimalBST(int **root, int i, int j, int parent, char side) {

    /* Empty subtree */
    if (i > j) {
        printf("Dummy key d%d is the %s child of key k%d\n",
               i - 1,
               side == 'L' ? "left" : "right",
               parent);
        return;
    }

    int r = root[i][j];

    /* Root of the entire tree */
    if (parent == -1) {
        printf("Root = k%d\n", r);
    }
    else {
        printf("k%d is the %s child of k%d\n",
               r,
               side == 'L' ? "left" : "right",
               parent);
    }

    /* Construct left subtree */
    printOptimalBST(root, i, r - 1, r, 'L');

    /* Construct right subtree */
    printOptimalBST(root, r + 1, j, r, 'R');
}

int main() {

    int n;

    printf("Enter number of keys: ");
    scanf("%d", &n);

    /*
     * p[1...n] = successful probabilities
     * q[0...n] = unsuccessful probabilities
     */
    double *p = (double *)malloc((n + 1) * sizeof(double));
    double *q = (double *)malloc((n + 1) * sizeof(double));

    /*
     * DP tables
     */
    double **e =
        (double **)malloc((n + 2) * sizeof(double *));

    double **w =
        (double **)malloc((n + 2) * sizeof(double *));

    int **root =
        (int **)malloc((n + 2) * sizeof(int *));

    if (p == NULL || q == NULL ||
        e == NULL || w == NULL || root == NULL) {

        printf("Memory allocation failed.\n");
        return 1;
    }

    for (int i = 0; i <= n + 1; i++) {

        e[i] =
            (double *)malloc((n + 2) * sizeof(double));

        w[i] =
            (double *)malloc((n + 2) * sizeof(double));

        root[i] =
            (int *)malloc((n + 2) * sizeof(int));

        if (e[i] == NULL ||
            w[i] == NULL ||
            root[i] == NULL) {

            printf("Memory allocation failed.\n");
            return 1;
        }
    }

    /*
     * Input successful probabilities
     */
    printf("\nEnter successful search probabilities p1 to p%d:\n", n);

    for (int i = 1; i <= n; i++) {
        printf("p[%d] = ", i);
        scanf("%lf", &p[i]);
    }

    /*
     * Input unsuccessful probabilities
     */
    printf("\nEnter unsuccessful search probabilities q0 to q%d:\n", n);

    for (int i = 0; i <= n; i++) {
        printf("q[%d] = ", i);
        scanf("%lf", &q[i]);
    }

    /*
     * Base cases
     *
     * e[i][i-1] represents an empty subtree
     * containing dummy key d(i-1).
     */
    for (int i = 1; i <= n + 1; i++) {

        e[i][i - 1] = q[i - 1];

        w[i][i - 1] = q[i - 1];
    }

    /*
     * Bottom-Up Dynamic Programming
     */
    for (int length = 1; length <= n; length++) {

        for (int i = 1;
             i <= n - length + 1;
             i++) {

            int j = i + length - 1;

            /*
             * Initially set minimum cost to infinity.
             */
            e[i][j] = INF;

            /*
             * Calculate total probability.
             */
            w[i][j] =
                w[i][j - 1]
                + p[j]
                + q[j];

            /*
             * Try every possible root.
             */
            for (int r = i; r <= j; r++) {

                double cost =
                    e[i][r - 1]
                    + e[r + 1][j]
                    + w[i][j];

                if (cost < e[i][j]) {

                    e[i][j] = cost;

                    root[i][j] = r;
                }
            }
        }
    }

    /*
     * Display result
     */
    printf("\n========================================\n");
    printf("       OPTIMAL BINARY SEARCH TREE\n");
    printf("========================================\n");

    printf("\nMinimum Expected Search Cost = %.4lf\n",
           e[1][n]);

    /*
     * Reconstruct optimal BST
     */
    printf("\nOptimal BST Structure:\n");

    printOptimalBST(root, 1, n, -1, ' ');

    /*
     * Display DP cost table
     */
    printf("\nDP Cost Table:\n");

    for (int i = 1; i <= n; i++) {

        for (int j = i; j <= n; j++) {

            printf("e[%d][%d] = %.4lf\n",
                   i,
                   j,
                   e[i][j]);
        }
    }

    /*
     * Free memory
     */
    for (int i = 0; i <= n + 1; i++) {

        free(e[i]);
        free(w[i]);
        free(root[i]);
    }

    free(e);
    free(w);
    free(root);

    free(p);
    free(q);

    return 0;
}
```

# 21. Correctness Proof

We prove that the Dynamic Programming algorithm finds the minimum expected search cost.

## Base Case

For an empty subtree:

```text
e[i][i-1] = q[i-1]
```

There is only one dummy key, so this is the correct expected search cost.

---

## Inductive Hypothesis

Assume that all smaller subtrees have already been solved optimally.

That means:

```text
e[i][r-1]
```

contains the optimal cost of the left subtree, and:

```text
e[r+1][j]
```

contains the optimal cost of the right subtree.

---

## Inductive Step

For the subtree containing keys:

```text
ki ... kj
```

suppose `kr` is selected as its root.

The left and right subtrees must then contain:

```text
Left  = ki ... k(r-1)

Right = k(r+1) ... kj
```

By the inductive hypothesis, their stored DP values are optimal.

When these subtrees become children of `kr`, every search in the subtree increases in depth by one. The total probability of all such searches is:

```text
w[i][j]
```

Therefore the total cost when `kr` is the root is:

$$
e[i][r-1]+e[r+1][j]+w[i][j]
$$

The algorithm checks every possible root:

```text
r = i, i+1, ..., j
```

and chooses the smallest cost.

Therefore:

$$
e[i][j]
$$

is the minimum possible expected search cost for that subtree.

Hence:

$$
e[1][n]
$$

is the minimum expected search cost for the complete set of keys.

---

# 22. Correctness of Reconstruction

The `root[][]` table stores the root that produced the minimum cost for every interval.

For example:

```text
root[1][n] = r
```

means that `kr` is the optimal root of the complete tree.

The algorithm then recursively constructs:

```text
Left subtree  → [1, r-1]

Right subtree → [r+1, n]
```

using the corresponding `root[][]` values.

Therefore, all nodes are placed according to the optimal decisions recorded by the DP algorithm.

Hence, the reconstructed tree is an optimal BST.

# 23. Complexity Analysis

There are `O(n²)` possible intervals.

For every interval `[i,j]`, we try every possible root:

```text
r = i, i+1, ..., j
```

In the worst case there are `O(n)` possible roots.

Therefore:

$$
O(n^2)\times O(n)
$$

$$
=\boxed{O(n^3)}
$$

### Time Complexity

$$
\boxed{O(n^3)}
$$

---

## Space Complexity

The algorithm maintains three tables:

```text
e[][]
w[][]
root[][]
```

Each has approximately `n × n` entries.

Therefore:

$$
\boxed{O(n^2)}
$$

space is required.

| Operation                   | Time Complexity | Space Complexity |

| Initialize base cases       |          `O(n)` |          `O(n²)` |
| Calculate probability table |         `O(n²)` |          `O(n²)` |
| Calculate optimal costs     |         `O(n³)` |          `O(n²)` |
| Reconstruct tree            |          `O(n)` | `O(n)` recursion |
| **Overall**                 |       **O(n³)** |        **O(n²)** |

# 25. Important Points

### Point 1: Keys must be sorted

The keys must satisfy:

$$
k_1 < k_2 < \cdots < k_n
$$

because the structure must remain a valid Binary Search Tree.

### Point 2: Probabilities

Normally the probabilities satisfy:

$$
\sum_{i=1}^{n}p_i+\sum_{i=0}^{n}q_i=1
$$

### Point 3: Dummy Keys

Dummy keys represent unsuccessful searches and are essential for calculating the complete expected search cost.

### Point 4: `root[][]`

The `root[][]` table is not required if we only want the minimum cost, but it is necessary when we want to reconstruct the actual optimal BST.

### Point 5: `w[][]`

The `w[][]` table avoids repeatedly calculating the total probability of every interval.

# 26. Difference Between Normal BST and OBST

| Normal BST                                         | Optimal BST                                  |
| -------------------------------------------------- | -------------------------------------------- |
| Usually constructed based on insertion/order       | Constructed using search probabilities       |
| Does not necessarily minimize expected search cost | Minimizes expected search cost               |
| Search frequencies may be ignored                  | Search frequencies are explicitly considered |
| Can be constructed using standard BST insertion    | Usually solved using Dynamic Programming     |
| Dummy searches are usually not considered          | Dummy keys are explicitly considered         |

# 27. Key Formulae

### Empty Subtree

$$
\boxed{e[i][i-1]=q_{i-1}}
$$

### Total Probability

$$
\boxed{
w[i][j]=w[i][j-1]+p_j+q_j
}
$$

### Optimal Cost

$$
\boxed{
e[i][j]
=
\min_{i\leq r\leq j}
\left[
e[i][r-1]+e[r+1][j]+w[i][j]
\right]
}
$$

### Final Answer

$$
\boxed{e[1][n]}
$$
