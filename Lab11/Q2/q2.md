Multi-Source BFS for Radius-Constrained Voronoi Cell Partitioning
1. Problem Statement
Given an unweighted, undirected graph G = (V, E), a set of K hubs H = {h1, h2, ..., hK}, and a non-negative radius R, assign every vertex to a hub:
1. Find the shortest-path distance from the vertex to every hub.
2. If the minimum distance is greater than R, assign owner -1.
3. Otherwise, assign the vertex to the closest hub.
4. If multiple hubs are equally close, choose the hub with the smallest index.
For every vertex, output its owner and distance to that hub. For unassigned vertices, this README uses distance -1.
2. Approach: Multi-Source BFS
A normal BFS starts from one source. Multi-source BFS starts from all hubs simultaneously by placing every hub in the queue before traversal begins. Because the graph is unweighted, BFS finds shortest paths by number of edges.

For each vertex v, maintain:
- dist[v]: shortest distance to the closest hub.
- owner[v]: index of the hub that owns v, or -1 if uncovered.
Initialization
1. Build an adjacency list for the undirected graph.
2. Set dist[v] = -1 and owner[v] = -1 for every vertex.
3. For each hub hi with index i, set dist[hi] = 0 and owner[hi] = i.
4. Insert all distinct hubs into the queue.
BFS traversal
While the queue is not empty:
1. Remove a vertex u.
2. If dist[u] == R, do not expand it further. Its neighbors would be at distance R + 1 through this path, outside the coverage radius.
3. For each neighbor v, calculate newDist = dist[u] + 1.
4. If v has not been visited, set dist[v] = newDist, set owner[v] = owner[u], and enqueue it.
5. If newDist equals the current shortest distance to v, choose the smaller hub index.
Tie-breaking note: To guarantee deterministic ownership, process hubs in increasing index order and ensure equal-distance ownership updates are handled correctly. A robust implementation can enqueue a vertex again when its owner changes, or process the BFS layer by layer so the smallest-index owner is settled before the next layer is expanded.
Final output
For every vertex v:
- If it was not reached within radius R, print owner -1 and distance -1.
- Otherwise, print owner[v] and dist[v].
3. Why Multi-Source BFS Works
All edges have weight one, so BFS explores vertices in nondecreasing distance order. Starting from all hubs simultaneously finds the minimum distance to any hub. The search stops expanding vertices at distance R, so it does not explore beyond the coverage radius.

When multiple hubs are at the same minimum distance, the tie-breaking rule selects the smallest hub index.
4. Graph Representation
Use an adjacency list. For each undirected edge (u, v), add v to u's list and u to v's list.

An adjacency list uses O(V + E) memory and is efficient for sparse graphs.
5. Example
Edges:
1 2
2 3
2 5
5 4
5 6
The graph can be visualized as:
1 -- 2 -- 3
     |
     5 -- 4
     |
     6
Let hub index 1 be vertex 1, hub index 2 be vertex 5, and R = 2.
Vertex	Distance to hub 1	Distance to hub 2	Owner	Reported distance
1	0	2	1	0
2	1	1	1	1
3	2	2	1	2
4	3	1	2	1
5	2	0	2	0
6	3	1	2	1


Vertex 2 is equally close to both hubs (distance 1), so it is assigned to hub 1, whose index is smaller. Vertex 4 belongs to hub 2 because it is closer to vertex 5.

Expected output:
Vertex  Owner  Distance
1       1      0
2       1      1
3       1      2
4       2      1
5       2      0
6       2      1
6. Input Format
n m K R
u1 v1
u2 v2
...
um vm
h1 h2 ... hK
- n: number of vertices, numbered 1 through n
- m: number of undirected edges
- K: number of hubs
- R: maximum coverage distance
- Next m lines: undirected edges u v
- Final line: hub vertices in index order. The first listed hub has index 1, the second has index 2, and so on.
Assume hubs are distinct, as they form a set.
7. Complexity Analysis
Let V be the number of vertices and E the number of edges.
- Time complexity: O(V + E) for adjacency-list construction and multi-source BFS, provided each vertex and edge is processed a constant number of times and tie-breaking is implemented without repeated unbounded reprocessing.
- Space complexity: O(V + E) for the adjacency list, queue, owner array, and distance array.
8. Key Insight
Insert all hubs into one queue and run BFS only as far as radius R. Each vertex is assigned to a nearest hub, ties go to the smallest hub index, and vertices outside all hub radii remain unassigned (owner = -1).
