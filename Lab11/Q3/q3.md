Bidirectional BFS for Shortest Word Transformation
1. Problem Statement
Given a dictionary D containing N unique words of equal length L, a starting word A, and a target word B, find the minimum number of mutations needed to transform A into B.

A mutation changes exactly one character, and every resulting word must belong to the dictionary. The starting word A may be outside the dictionary, but the target word B must be present in it.

If no valid transformation exists, return -1.
Constraints
- N <= 100000
- L <= 10
- All words contain only lowercase English letters (a to z).
2. Approach: Bidirectional BFS
Breadth-First Search (BFS) is suitable because every valid mutation has an equal cost of one. BFS explores words level by level, so it finds a path with the minimum number of mutations.

Instead of running BFS only from the starting word, use Bidirectional BFS:
- The forward search begins at A.
- The backward search begins at B.
- Both searches expand level by level.
- At each iteration, expand the smaller of the two current frontiers.
- When the searches meet at a word, combine the distances from both directions to obtain a transformation path.
Expanding the smaller frontier helps reduce the number of words explored.
3. Efficient Word Lookup Using Hashing
The dictionary can contain up to 100000 words. Checking every generated word against the entire dictionary would be inefficient.

To make membership checks faster, store the dictionary in a hash table.

For each word being explored:
1. Select one character position.
2. Replace its character with each of the other 25 lowercase letters.
3. Check whether the newly generated word exists in the dictionary using the hash table.
4. If it exists and has not already been visited in the current search, add it to that search's next BFS frontier.
Since each word has L positions, at most 25 * L candidate mutations are generated for one word.
4. Algorithm Steps
1. Read the dictionary, starting word A, and target word B.
2. Check whether B exists in the dictionary. If it does not, return -1.
3. If A and B are identical, return 0.
4. Initialize two BFS searches:
   - Forward frontier containing A.
   - Backward frontier containing B.
5. Maintain separate visited-distance information for both searches. Initially, the distance of each starting word is zero.
6. While both frontiers are non-empty:
   - Compare their sizes and choose the smaller frontier.
   - Generate all possible one-character mutations of every word in that frontier.
   - Ignore generated words that are not in the dictionary.
   - If a generated word has already been reached by the opposite search, calculate the combined distance.
   - Otherwise, if it has not been visited by the current search, record its distance and add it to the next frontier.
   - Process the complete current BFS level and choose the minimum distance among meeting points found at that level.
7. If the searches meet, return the minimum combined distance.
8. If either frontier becomes empty before the searches meet, return -1.
5. Example
Dictionary:

D = {hot, dot, dog, lot, log, cog}

Starting word: hit

Target word: cog

One shortest transformation sequence is:

hit -> hot -> dot -> dog -> cog

The mutations are:
1. hit to hot
2. hot to dot
3. dot to dog
4. dog to cog
Minimum number of mutations = 4
6. Why Bidirectional BFS?
A normal BFS explores outward from only one endpoint. Bidirectional BFS explores from both endpoints, so the two searches can meet before either one has explored a large portion of the graph.

For a graph with roughly uniform branching factor b and shortest-path depth d, a typical comparison is:
- Normal BFS: approximately O(b^d) explored nodes.
- Bidirectional BFS: approximately O(b^(d/2)) explored nodes from each side.
These are illustrative search-space estimates, not guaranteed bounds for every dictionary.

Expanding the smaller frontier further reduces unnecessary exploration.
7. Complexity Analysis
Let:
- N = number of words in the dictionary.
- L = length of each word.
- 26 = number of lowercase English letters.
Time Complexity
Each word is visited at most once from each search direction.

For every visited word:
- There are L character positions.
- At each position, at most 25 replacement characters are tried.
- Each generated word is checked in the hash table. Hashing and string comparison take O(L) time.
Therefore, the expected overall time complexity with this hash-table representation is:

O(26 * N * L^2)

Since L <= 10, word length is small and bounded. If hashing and word comparison are treated as constant-time operations for bounded-length words, the search work is commonly expressed as O(26 * N * L).

The hash table uses open addressing, so these are expected-time bounds under reasonable hash distribution; collisions can increase lookup time.
Space Complexity
The algorithm stores:
- Dictionary words: O(N * L)
- Hash table: O(N) entries (or the chosen table capacity)
- Visited-distance information for both searches: O(N)
- Two BFS frontiers and their next-level storage: O(N)
Overall space complexity:

O(N * L)
8. Conclusion
Bidirectional BFS combined with hashing is an efficient approach for finding the minimum number of mutations in a word-transformation problem.
- BFS guarantees a shortest transformation because every mutation has equal cost.
- Bidirectional search explores from both the starting and target words.
- Expanding the smaller frontier helps reduce the search space.
- Hashing allows efficient dictionary membership checks.
- The algorithm returns -1 if no valid transformation exists.
This approach is suitable for the given constraints of up to 100000 dictionary words and word length up to 10.
