Maximum People Simultaneously Present — O(n log n)

Problem Statement

A camera at the door records the entry time aᵢ and exit time bᵢ for each of n people attending a party, where:

bᵢ > aᵢ

Determine the time when the maximum number of people were simultaneously present at the party.

Assumption:

All entry and exit times are distinct, so there are no ties.

The required time complexity is:

O(n log n)

Key Idea

Convert every person's entry and exit time into an event:

Entry → +1

Exit → -1

For each person (aᵢ, bᵢ):

(aᵢ, +1)
(bᵢ, -1)

There are 2n events in total.

Sort all events by time and scan them from left to right.

While scanning:

At an entry, increase the number of people currently present.

At an exit, decrease the number of people currently present.

Whenever the current number becomes greater than the previous maximum, store that time.

Because all times are distinct, no tie-handling is required.

Algorithm

1. Create two events for every person:
       (entry time, +1)
       (exit time, -1)

2. Sort all 2n events by time.

3. Set:
       currentPeople = 0
       maxPeople = 0
       maxTime = 0

4. Scan the sorted events:
       If event is an entry:
           currentPeople++

           If currentPeople > maxPeople:
               maxPeople = currentPeople
               maxTime = event.time

       Else:
           currentPeople--

5. Return maxTime and maxPeople.

Why Does It Work?

At any point in time, the number of people present is exactly:

number of entries seen - number of exits seen

Therefore, while scanning events in chronological order, currentPeople always represents the number of people currently inside the party.

Whenever currentPeople reaches a new maximum, that event's time is the first time the maximum is reached.

Thus, after processing all events, maxTime gives the required time.

Time Complexity

There are n entry events and n exit events:

Total events = 2n

Sorting

Sorting 2n events takes:

O(2n log(2n))

Ignoring constant factors:

O(n log n)

Scanning

We scan all 2n events once:

O(2n) = O(n)

Total

O(n log n) + O(n)

Therefore:

[
\boxed{O(n\log n)}
]

Space Complexity

We store 2n events:

[
\boxed{O(n)}
]

Summary

The main idea is:

Convert every entry and exit into an event, sort all events by time, and maintain a running count of people present.

This avoids comparing every pair of people and gives the required:

[
\boxed{O(n\log n)}
]

time complexity.
