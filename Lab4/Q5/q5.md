Merging Overlapping Intervals — O(n log n)

Problem Statement

Given a list I of n intervals, where each interval is represented as (xᵢ, yᵢ), merge all overlapping intervals.

For example:

Input:
{(1,3), (2,6), (8,10), (7,18)}

Output:
{(1,6), (7,18)}

The algorithm must run in worst-case:

[
O(n\log n)
]

Key Idea

The main observation is that if the intervals are sorted by their starting point, overlapping intervals will appear next to each other.

Step 1 — Sort

Sort all intervals according to their starting point.

For:

(1,3), (2,6), (8,10), (7,18)

we get:

(1,3), (2,6), (7,18), (8,10)

Step 2 — Scan and Merge

Start with the first interval.

For each next interval:

If its starting point is less than or equal to the current interval's ending point, the intervals overlap.

Extend the current ending point if necessary.

Otherwise, save the current interval and start a new interval.

Example

Sorted intervals:

(1,3), (2,6), (7,18), (8,10)

Compare (1,3) and (2,6)

Since:

2 <= 3

they overlap.

Merge them:

(1,6)

Compare (1,6) and (7,18)

Since:

7 > 6

they do not overlap.

Save:

(1,6)

and start:

(7,18)

Compare (7,18) and (8,10)

Since:

8 <= 18

they overlap.

The ending point remains 18.

Final result:

{(1,6), (7,18)}

Algorithm

1. Sort all intervals by their starting point.
2. Set current interval = first interval.
3. For every remaining interval:
       If next.start <= current.end:
           current.end = max(current.end, next.end)
       Else:
           Add current to result.
           current = next
4. Add the final current interval to result.
5. Return the result.

Correctness

After sorting, every interval that can overlap the current interval appears after it and before any interval that starts beyond the current ending point.

If:

next.start <= current.end

then the two intervals overlap, so they can safely be represented by one interval:

(current.start, max(current.end, next.end))

If:

next.start > current.end

then there is a gap between the intervals, so the current interval can no longer overlap any later interval. It is therefore safe to add it to the result.

Thus, after scanning all intervals, the result contains exactly the merged non-overlapping intervals.

Input and Output Representation

Sample Run

Input

Enter number of intervals: 4
Enter intervals (start end):
1 3
2 6
8 10
7 18

Output

Merged intervals:
(1,6) (7,18)

Time Complexity

Sorting

Merge Sort takes:

[
O(n\log n)
]

Merging

The intervals are scanned once:

[
O(n)
]

Total

[
O(n\log n)+O(n)
]

Therefore:

[
\boxed{O(n\log n)}
]

The sorting step dominates the running time.

Space Complexity

The input and result arrays require:

[
\boxed{O(n)}
]

additional space.

Summary

The key idea is:

Sort the intervals by their starting points, then scan from left to right and merge whenever the next interval starts before or at the current ending point.

This gives the required worst-case complexity:

[
\boxed{O(n\log n)}
]
