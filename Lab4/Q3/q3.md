k-Sum Problem — O(n^(k-1) · log n)

Problem Statement

Given a set S of n integers and an integer T, determine whether there exist k distinct integers in S whose sum is equal to T.

The required time complexity is:

[
O(n^{k-1}\log n)
]

The algorithm below assumes that k is treated as a fixed constant.

Key Idea

The simplest way to achieve the required complexity is:

Sort the set S.

Generate every possible combination of k - 1 elements.

For each combination, calculate the value that the final element must have.

Use binary search to check whether that required value exists in S.

If:

[
a_1+a_2+\cdots+a_{k-1}+a_k=T
]

then the required final value is:

[
a_k=T-(a_1+a_2+\cdots+a_{k-1})
]

So instead of trying every possible group of k elements, we choose the first k-1 elements and search for the final element.

Example

Suppose:

S = {1, 3, 5, 7, 9}
k = 3
T = 15

Choose two elements:

1 + 5 = 6

The required third element is:

required = 15 - 6
         = 9

Since 9 exists in S:

1 + 5 + 9 = 15

Therefore, a valid set of 3 elements exists.

Algorithm

1. Sort S.
2. Generate every combination of k - 1 elements.
3. For each combination:
       sum = sum of the selected k - 1 elements
       required = T - sum

       Binary search for required in S.

       If required is found:
           Return YES
4. Return NO.

When the elements must be distinct, the binary search result should not reuse one of the already selected elements. The C implementation handles this by checking the candidate index.

Why Does It Work?

Suppose a valid solution exists:

[
a_1+a_2+\cdots+a_k=T
]

The algorithm eventually considers the first k - 1 elements of this solution.

It then calculates:

[
required=T-(a_1+a_2+\cdots+a_{k-1})
]

From the original equation:

[
required=a_k
]

Therefore, the binary search will find the final element, and the algorithm will report that a solution exists.

If no combination of k - 1 elements produces a required value present in S, then no valid group of k elements can sum to T.

Time Complexity

Sorting

Sorting S using Merge Sort takes:

[
O(n\log n)
]

Generating combinations

There are:

[
O(n^{k-1})
]

possible ordered choices for k - 1 elements when k is a fixed constant.

Binary Search

For every choice, binary search takes:

[
O(\log n)
]

Therefore:

[
O(n^{k-1})\times O(\log n)
]

[
\boxed{O(n^{k-1}\log n)}
]

The initial sorting cost O(n log n) is smaller than the main term for fixed k >= 2, so the overall complexity is:

[
\boxed{O(n^{k-1}\log n)}
]

Summary

The main trick is:

Choose k - 1 elements and use binary search to find the one remaining element required to make the sum equal to T.

Therefore:

[
\boxed{\text{Time Complexity} = O(n^{k-1}\log n)}
]

and the input can conveniently be represented using a simple integer array
