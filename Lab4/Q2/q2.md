Two-Sum Across Two Sets — O(n log n)

Problem Statement

Given two sets S1 and S2, each containing n elements, and a number x, determine whether there exists a pair of elements — one from S1 and one from S2 — whose sum is equal to x.

Formally, determine whether there exist:

a ∈ S1 and b ∈ S2

such that:

a + b = x

The required time complexity is O(n log n).

Approach

The key observation is:

For every element a in S1, the element required from S2 is:

b = x - a

Therefore, we can:

Sort S2.

For every element a in S1:

Calculate required = x - a.

Perform a binary search for required in sorted S2.

If the required value is found, a valid pair exists.

If no required value is found after checking all elements of S1, no such pair exists.

Example

Input

S1 = {2, 5, 8, 10}
S2 = {1, 3, 6, 9}
x = 11

Sort S2:

S2 = {1, 3, 6, 9}

Check the elements of S1:

For a = 2:

required = 11 - 2 = 9

9 exists in S2.

Therefore:

2 + 9 = 11

So a valid pair exists.

Algorithm

Sort S2 using Merge Sort.

For every element a in S1:
    required = x - a

    If required exists in S2 using Binary Search:
        Return YES

Return NO

Why Does It Work?

For any element a from S1, the only value that can form the required sum x is:

x - a

So checking whether x - a exists in S2 is exactly equivalent to checking whether a has a matching partner in S2.

Since every element of S1 is checked, no possible pair is missed.

Time Complexity

1. Sorting S2

Using Merge Sort:

O(n log n)

2. Binary Search

There are n elements in S1.

Each binary search takes:

O(log n)

Therefore:

n × O(log n) = O(n log n)

3. Total

O(n log n) + O(n log n)
= O(2n log n)
= O(n log n)

Therefore:

Time Complexity = O(n log n)

Space Complexity

The arrays require:

O(n) space.
Sample Run

Input

Enter size of each set: 4
Enter elements of S1:
2 5 8 10
Enter elements of S2:
1 3 6 9
Enter x: 11

Output

Pair exists: (2, 9)

Because:

2 + 9 = 11

Key Idea

The entire algorithm is based on one simple idea:

For every a in S1, search for x - a in S2.

Sorting S2 allows us to use binary search, giving the required:

O(n log n) time complexity.
