Maximum Overlap Point in a Set of Intervals — O(n log n)

Problem Statement

Given a set S of n intervals on a line, where the ith interval is represented by its left and right endpoints:

(li, ri)

identify a point p on the line that belongs to the largest number of intervals.

An endpoint counts as being inside its interval.

Example

S = {(10,40), (20,60), (50,90), (15,70)}

No point belongs to all four intervals.

For example, p = 50 belongs to:

(20,60)
(50,90)
(15,70)

Therefore, the maximum number of overlapping intervals is 3.

Another valid answer is p = 20, which also lies in three intervals.

Key Idea

Use a sweep-line algorithm.

For every interval (l, r), create two events:

(l, +1)   → interval starts
(r, -1)   → interval ends

There are 2n events in total.

Sort all events by their position and then scan them from left to right while maintaining the number of currently active intervals.

Important

Because an endpoint counts as being inside an interval, if a start and an end occur at the same point, the start event must be processed before the end event.

Algorithm

1. Create two events for every interval:
       (left endpoint, +1)
       (right endpoint, -1)

2. Sort all 2n events:
       - Sort by position.
       - If positions are equal, put +1 before -1.

3. Set:
       current = 0
       maximum = 0
       answer = 0

4. Scan the sorted events:
       If event is +1:
           current++

           If current > maximum:
               maximum = current
               answer = event.position

       Else:
           current--

5. Return answer and maximum.

Why Does It Work?

At any point during the sweep:

current = number of intervals that have started
          - number of intervals that have ended

Therefore, current represents the number of intervals containing the current point.

Whenever current becomes larger than the previous maximum, that point has the largest overlap seen so far.

Because every interval contributes exactly one start and one end event, every possible change in the number of active intervals is considered.

Thus, the algorithm finds a point contained in the maximum possible number of intervals.

Why Process Start Before End?

Suppose we have:

(10,20)
(20,30)

At p = 20, both intervals contain the point because endpoints count.

So the correct count at 20 is:

2

The events at 20 are:

20  Start
20  End

Processing Start first gives:

current = 2

before the ending interval is removed.

Therefore, the algorithm correctly handles endpoint inclusion.

Input and Output Representation

A struct is a suitable representation for an event:

typedef struct {
    int point;
    int type;   // +1 = start, -1 = end
} Event;

The input intervals are converted into an array containing 2n events.

The output consists of:

the point with maximum overlap

the maximum number of intervals containing that point

Time Complexity

There are 2n events.

Sorting

Merge Sort takes:

O(2n log(2n))

which simplifies to:

[
O(n\log n)
]

Sweep

The sorted events are scanned once:

[
O(2n)=O(n)
]

Total

[
O(n\log n)+O(n)
]

Therefore:

[
\boxed{O(n\log n)}
]

The sorting step dominates the running time.

Space Complexity

We store 2n events:

[
\boxed{O(n)}
]

Summary

The main idea is:

Convert every interval into a start event (+1) and an end event (-1), sort the events, and keep a running count of active intervals.

Since endpoints count, process a start before an end at the same point.

Final complexity:

[
\boxed{\text{Time: }O(n\log n)}
]

[
\boxed{\text{Space: }O(n)}
]
